## Sobre mim · <sub>About</sub>

Tenho 20 anos, moro em Sorocaba (SP) e construo minha carreira na interseção entre **engenharia de back-end** e **sistemas de gestão empresarial**.

Trabalho na **Faktory Softwares** como Consultor de Implantação. Meu dia envolve levantar regras de negócio com empresas, parametrizar o ERP, treinar usuários, validar funcionalidades e levar os problemas encontrados até os times de desenvolvimento e qualidade. Também produzo manuais e documentação que reduzem o atrito na adoção do sistema.

Faço parte da linha de frente do **Faktory Flow**, uma plataforma web voltada a empresas da indústria de esquadrias, com foco em ser moderna, funcional e didática para quem usa. Participar da concepção de um produto — e não só da entrega dele — mudou a forma como eu penso software: acompanho de perto como uma decisão técnica vira (ou não) valor para o usuário final.

Minha especialização é **back-end com Java e Spring Boot**: APIs REST, modelagem de dados, segurança com JWT e organização do código em camadas bem definidas. É onde estou mais forte e onde continuo aprofundando.

Em paralelo, avanço em **arquitetura de software, microsserviços, containerização e cloud** — áreas em que estudo com consistência e já aplico em projetos próprios. Uso **inteligência artificial de forma estratégica** no dia a dia, para acelerar pesquisa técnica, estruturar documentação e prototipar ideias. Ferramenta, não atalho: o que a IA produz passa por validação, teste e critério meu antes de virar entrega.

## Projetos em destaque · <sub>Featured projects</sub>

### NEO Energy — API de gestão energética e irrigação

Plataforma para gerenciar painéis solares e irrigação automatizada de uma residência. Cada ciclo de irrigação vira uma sessão registrada com período, duração e consumo de água, permitindo acompanhar o gasto real ao longo do tempo.

**Minha contribuição:** back-end completo — modelagem do domínio, API REST, autenticação e autorização, e containerização.

**Stack:** Java 21 · Spring Boot · Spring Security · Spring Data JPA · JWT · PostgreSQL · MapStruct · Docker · Maven

**Decisão técnica:** implementei *refresh token com rotação* — cada renovação invalida o token anterior, limitando a janela de exploração caso um token vaze. A sessão é `STATELESS` e a autorização é granular por endpoint com `@PreAuthorize`, em vez de concentrada numa única regra global.

[`Código`](https://github.com/Pcamargoz/NeoEnergy---Facens) · [`Aplicação`](https://front-end-neo-energy.vercel.app/) · [`Vídeo`](https://youtu.be/d_CgiWGqPuU)

<br>

### CultivaClub — de três microsserviços a um monolito modular

Consolidação de três serviços independentes (usuários, objetos e gateway) em uma única aplicação Spring Boot. O sistema gerencia cards de cultivo, tarefas e calendário.

**Minha contribuição:** refatoração da arquitetura, reorganização do código por domínio e simplificação do pipeline de deploy.

**Stack:** Java 21 · Spring Boot · Spring Security · OAuth2 · JPA/Hibernate · PostgreSQL · HikariCP · Docker

**Decisão técnica:** manter os bancos dos módulos herdados fisicamente separados dentro do monolito, com dois `EntityManagerFactory` e dois `TransactionManager` configurados por domínio. A fronteira entre os módulos sobreviveu à fusão — o que preserva a possibilidade de extrair um serviço de volta no futuro sem desembaraçar tabelas.

[`Código`](https://github.com/Pcamargoz/Projeto-Cultiva-Club-Back-End-Monolito-) · [`Vídeo`](https://youtu.be/Y_FaWIzn7W4)

<br>

### Criador de Subagents — orquestração de agentes de IA

Aplicação web para montar times de agentes especializados: catálogo de papéis, sequência de execução, regras de comunicação e entregas por fase. Nasceu de uma necessidade própria — padronizar o uso de LLMs em tarefas técnicas repetitivas.

**Minha contribuição:** concepção do produto, interface e integração com a API.

**Stack:** React · TypeScript · Vite · Tailwind CSS · back-end em Spring Boot com autenticação JWT

**Decisão técnica:** toda comunicação HTTP passa por um cliente único, que injeta o token, normaliza o formato de erro da API e encerra a sessão automaticamente em respostas `401`. Nenhum componente conhece a rede — o que mantém a interface independente do contrato do back-end.

[`Código`](https://github.com/Pcamargoz/Criador-De-Subagents) · [`Aplicação`](https://criador-de-subagents.vercel.app)

<br>

### SwapStudy — JDBC e o padrão DAO na mão

Sistema de usuários e contratos escrito em Java puro, sem framework, para entender por dentro o que o Spring Data abstrai: conexão, transação, tratamento de erro de integridade e mapeamento objeto-relacional.

**Minha contribuição:** modelagem, camada de persistência e liderança do time no projeto acadêmico.

**Stack:** Java · JDBC · MySQL

**Decisão técnica:** uma `DaoFactory` como ponto único de instanciação, devolvendo sempre a interface (`UsuarioDao`, `ContratoDao`) e nunca a implementação JDBC. Trocar a tecnologia de persistência não exigiria tocar em nenhum consumidor — o mesmo princípio que hoje aplico com Spring, só que explícito.

[`Código`](https://github.com/Pcamargoz/Projeto-JavaSQL-SwapStudy)
